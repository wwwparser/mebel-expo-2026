# Контракт входных данных

Все файлы — UTF-8. Модули хранятся в `data/portal/<module>.json` как массивы объектов; отсутствующий необязательный файл равен пустому массиву. Нет автоматического импорта из прежних проектов. Структура массивов и уникальность ID проверяются даже у отключённых модулей. Дальнейшие поля валидируются у выбранных непустых модулей.

## Конфигурация `expo.json`

| Поле | Назначение |
| --- | --- |
| `name`, `edition`, `place` | Обязательные непустые фактические подписи. Выпуск — строка, не обязательно год. |
| `start_date`, `end_date` | Обязательные полные ISO-даты `YYYY-MM-DD`, конец не раньше начала. |
| `dates_label` | Необязательная редакционная подпись; при отсутствии выводятся полные даты. |
| `timezone` | Обязательный часовой пояс IANA. На Windows используется зависимость `tzdata`. |
| `checked_at` | Обязательная дата или ISO datetime реального среза. Время с offset предпочтительно. |
| `official_url`, `catalog_url`, `scheme_url` | Проверенные http/https-ссылки либо пустые строки. |
| `base_url` | Абсолютный адрес публикации вместе с подкаталогом, без query/fragment; пустой для локальной сборки. |
| `output_dir` | Относительный каталог вывода внутри проекта, по умолчанию `docs`. |
| `modules` | Массив из `participants`, `program`, `people`, `posts`, `giveaways`, `services`, `videos`, `novelties`, `articles`, `map`. `participants` обязателен. |
| `feed_count` | Положительное целое: начальное число публикаций в ленте, число на главной и в профиле. |
| `labels` | Необязательный объект `module: подпись`. |
| `intro` | Необязательный авторский текст первого экрана. |

## Общие поля записей

`id` обязателен: уникальная в файле строка из ASCII-букв, цифр, `_`, `-`. Только у постов допускается также исходный ID `channel/123`; он не используется как путь файла. У всех публичных записей обязательны `sources: [{title, url, date?, note?}]` с непустой библиографией и безопасными http/https-ссылками. Это происхождение записи, а не автоматически подтверждённая истинность текста. `checked_at` — необязательная собственная дата среза.

`participant_ids` и `people_ids` — массивы строковых ID для перекрёстных ссылок. Неизвестный ID участника останавливает сборку. Ссылки на отсутствующий или отключённый профиль спикера не выводятся. Не объединяйте тёзок без источников. Необязательный пустой раздел не создаётся; `map` создаётся только при выбранном модуле и непустой `scheme_url`.

## Поля модулей

| Файл | Поля помимо общих |
| --- | --- |
| `participants.json` | Обязательный непустой массив; `name`. Необязательные `about`, `country`, `stands: [строка]`, `halls: [строка]`, `categories: [строка]`, `rubrics: [{name, values: [строка]}]`, `logo`, `screenshot`, `contacts_text`, `contacts`, `media`, `materials`, `news`. |
| `people.json` | `name`; необязательные `role`, `about`, `photo`, `contacts`, `media`. Выступления связываются через `program.people_ids`, публикации — через каналы и посты. |
| `program.json` | `title`, `date: YYYY-MM-DD/null`, `start: HH:MM/null`, необязательные `end: HH:MM/null`, `venue`, `description`, `people_ids`, `participant_ids`. Время без полной даты запрещено. Отсутствующая дата показывается отдельным блоком. |
| `channels.json` | Справочник для постов: `id`, `title`, `url`, необязательные `participant_ids`, `people_ids`. Один ID на общий канал. `sources` не требуется: ссылка на канал и источники постов заданы отдельно. |
| `posts.json` | `id`, `channel_id`, `url`, `text` как обычный текст, `published_at` как полная ISO-дата/datetime или null. Необязательные `photos: [путь/URL]`, `participant_ids`, `people_ids`, `edited_at`, `grouped_message_ids`. Фотографии показываются максимум две. Текст HTML всегда экранируется и сокращается. |
| `giveaways.json` | `title`, `when: полная ISO-дата/datetime/null`, `review_status: reviewed/needs_review`, необязательные `status: cancelled`, `kind`, `stand`, `hall`, `prizes: [строка]`, `conditions: [строка]`, `entry_deadline`, `results_at`, `note`, связи. `when` — время события, не поста. Частичную дату не достраивать. Отмена без ясной даты остаётся в требующих уточнения. |
| `services.json` | `title` или `name`, авторские `description`, `evidence` — точная выдержка о реально оказываемой услуге, `participant_ids`, необязательные `url`, `image`. Отбор по услуге внешним клиентам выполняется до сборки. |
| `videos.json`, `novelties.json` | `title` или `name`; необязательные `description`, `evidence`, `url`, `image`, связи. Видео представлено внешней ссылкой, встраиваемые плееры не запускаются. |
| `articles.json` | `title`, `content_file` — относительный путь к предоставленному HTML-фрагменту внутри `data/portal/`, необязательные `summary`, `author`, `checked_at`; библиография обязательна. Полный HTML-документ, script/iframe/form, стили и обработчики событий запрещены. |

`contacts` — массив `{label, value, url?}`. URL допускает http/https/mailto/tel; небезопасная ссылка превращается в обычный текст, не выполняется. `media` — массив `{title, type, path?, url?, download_status?}`: `type=image` показывает изображение; прочие типы — ссылку. Статусы: `downloaded`, `external_only`, `unavailable`, `not_downloaded`. У `downloaded` файл обязан существовать. `materials` и `news` — массивы `{title, text}` с исходным текстом карточки, без автоматического пересказа.

Пути `logo`, `photo`, `screenshot`, `image`, `photos` и локальные вложения начинаются с `media/`, не содержат `..`, percent-escape, query, fragment и обратных слешей. Локальный файл должен уже находиться в выходном каталоге. Отсутствующая необязательная картинка не выводится. Внешние картинки допускают только http/https. Из `media/` сборщик ничего не удаляет и туда не пишет. Ссылки статей допускают http/https, локальные якоря и существующие файлы `media/`; статья публикуется как `article-<id>.html`.

## Необязательный анализ постов

`data/portal/post_analysis.jsonl` содержит по одному JSON-объекту на строку, уникальный `post_id`. Для отображения классификации необходимы одновременно:

- `review_status: verified`;
- `task_version: expo-post-v3`;
- `input_hash`, точно равный `scripts/build_portal.py:analysis_hash(config, raw_post)`.

Метаданные `classification` и `relevance` должны принадлежать допустимым перечислениям очереди; в интерфейсе выводятся их русские подписи только после этой проверки. Прочие поля очереди (`evidence`, `events`, модель, стоимость, проверяющий) не превращаются сборщиком в факты. Новые/изменённые посты остаются с подписью «Разбор ожидается»; публикация выдержки не блокируется.

Хеш — SHA256 UTF-8 canonical JSON (`sort_keys=True`, `separators=(',', ':')`, `ensure_ascii=False`) объекта:

```json
{
  "task_version": "expo-post-v3",
  "context": {"name": "...", "edition": "...", "start_date": "...", "end_date": "...", "timezone": "...", "catalog_url": "..."},
  "post": {"post_id": "строковый id", "text": "исходный text или пустая строка", "date": "date или published_at", "url": "url или permalink", "edited_at": null, "participant_ids": [], "people_ids": [], "media": [], "photos": [], "media_revision": null}
}
```

Отсутствующие ключи `context`, `edited_at`, date/url и media_revision становятся JSON null; отсутствующие `text` и массивы — соответственно пустой строкой и пустыми массивами. `media` здесь — исходный `grouped_message_ids`, не список картинок. `photos` берётся из photos, при отсутствии — remote_photos; media_revision хранит хеш/версию вложений, если адаптер может их проверить. Используется исходный пост **до** добавления связей общего канала. Изменение связей самого канала меняет отображаемые ссылки, но не превращает прежний анализ в новый. Не ставьте `verified` вручную без проверки смысловой точности и доказательств. Строгую полноту анализа проверяйте на этапе очереди до передачи материала в сборщик.

## Схема выставки

В переносимом комплекте поддержана только ссылка на официальную схему. Геометрия стендов, SVG-path и привязки к залам не предполагаются и не выдумываются. Для настоящей интерактивной карты нужен отдельный явно проверенный адаптер: источник и дата схемы, выпуск, уникальные ID компаний и залов, `viewBox`, безопасный локальный фон, координаты/контуры стендов в той же системе и сопоставление с `participants.id`. Не переносите координаты между выпусками автоматически. До такой интеграции используйте номера стендов в каталоге и официальную ссылку.
