# Переносимый портал выставки

Самостоятельный Python/Jinja2/JSON-проект. Сборка работает офлайн, не скачивает данные, не вызывает LLM и ничего не публикует. Требуется Python 3.10 или новее. Дизайн, CSS и основные компоненты сохранены из согласованного портала: светлая и тёмная темы, липкая шапка, статистика, карточки, фильтры, программа, лента и оформление больших материалов.

## Начать работу

1. Создайте проект через `scripts/init_portal.py` скилла: он скопирует шаблон вместе с очередью анализа. Для ручного копирования берите **весь этот каталог**; очередь скилла при этом добавляется отдельно. Удалять исходный шаблон не нужно.
2. В отдельном виртуальном окружении установите зависимости из `requirements.txt`.
3. Заполните `expo.json` данными конкретного выпуска. Пустые значения в комплекте намеренны: это не данные выставки. Название выпуска берите из каталога, даты задавайте полностью, часовой пояс — именем IANA. `base_url` можно оставить пустым до выбора хостинга; тогда canonical и sitemap не создаются.
4. Подготовьте `data/portal/participants.json` по [CONTRACT.md](CONTRACT.md). Пустой или отсутствующий каталог останавливает сборку. Старые каталоги и данные соседних проектов автоматически не подхватываются.
5. Выберите нужные модули в `modules`; добавьте их JSON-файлы. Непустые выбранные модули попадут в меню и на главную. Пустые необязательные разделы не создаются. Для карты достаточно проверенной `scheme_url`.
6. Локальные изображения, снимки исходных карточек и документы положите заранее в `<output_dir>/media/`. Сборщик только читает этот каталог. Путь в JSON начинается с `media/`; внешние файлы можно представить проверенными http/https-ссылками с явным статусом загрузки.

Команды из корня скопированного проекта:

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python scripts/build_portal.py
.venv/Scripts/python scripts/check_portal.py docs
.venv/Scripts/python -m http.server 8000 --directory docs
```

Если `output_dir` изменён, используйте его вместо `docs` в последних двух командах. `--root` выбирает другой проект; `--output` позволяет явно направить результат в другой каталог, например временный тестовый. Вывод внутри исходных каталогов и каталогов с именем `media` запрещён.

Первый запуск может потребовать интернет только для установки зависимостей. При просмотре браузер обращается к Google Fonts; при их недоступности работают системные шрифты. Вставки Telegram и сторонние видеоплееры автоматически не загружаются: публикации представлены статическими выдержками, а видео — ссылками на источники.

## Сборка и обновления

Обновите исходный JSON и реальную дату среза `checked_at`, затем повторите сборку и проверку. `checked_at` — дата предоставленного среза, а не обещание повторной проверки сборщиком. У отдельных записей может быть собственная дата среза. Произвольный текст и части дат не превращаются в даты текущего года.

Сборка сохраняет CSV/JSON каталога, относительные ссылки, уникальные страницы и canonical с учётом подкаталога `base_url`. При заданном `base_url` создаётся sitemap. `lastmod` сохраняется, если содержимое страницы не изменилось. Повторная идентичная сборка сохраняет байты и время изменения файлов. Версия CSS и JavaScript — хеш содержимого, а не ручной номер.

`.portal-manifest.json` содержит только принадлежащие сборщику файлы. При отключении раздела удаляются только ранее сгенерированные страницы. Чужие файлы и `media/` остаются. Не редактируйте manifest вручную. Исходные тексты редактируйте в JSON/HTML-фрагментах, оформление — в `portal_web/`, иначе следующая сборка заменит изменения в сгенерированных файлах.

Перед публикацией проверьте источники и полноту карточек, затем выполните браузерную проверку на компьютере и телефоне, `ui-verification` и аудит шести посетителей; сохраните снимки и отчёт в проекте. Скрипт проверки не заменяет просмотр в браузере. Публикация и аналитика подключаются отдельным явным действием.

## Материалы и разбор публикаций

Авторские статьи — предоставленные HTML-фрагменты и отдельные метаданные с библиографией. Сборщик ничего не дописывает, не переносит факты прежней выставки и не генерирует исследование рынка. Активный HTML, обработчики событий, небезопасные URL и произвольные пути отклоняются. Относительные вложения статьи разрешены только из `media/`; публичная страница статьи находится в корне сайта.

Один канал описывается один раз, даже если связан с несколькими участниками и спикерами. Тело публикации остаётся во входном JSON; в HTML попадает только выдержка до 45 слов. Публикация может отображаться без завершённого анализа. Метки анализа выводятся только при `review_status=verified`, версии `expo-post-v3` и точном совпадении хеша текста, ссылок, связей и контекста выпуска. После изменения текста или выпуска прежняя метка исчезает. Это совместимо с отдельным `analysis_queue.py` навыка, но зависимости от него у проекта нет.

Розыгрыши — отдельные редакционно проверенные записи. Не выводите их автоматически из слова «подарок» в посте. `when`, `entry_deadline` и `results_at` имеют разный смысл. Неясный статус проверки или отсутствие даты отправляют событие в «Требует уточнения», даже если прошедшая дата или отмена указана в записи. Статусы рассчитываются относительно `checked_at`, а не времени машины, и не подтверждают фактическое проведение.

## Безопасная демонстрация и самопроверка

```powershell
python scripts/smoke_test.py
```

Тест создаёт полностью синтетический проект во временном системном каталоге, собирает все модули и удаляет только собственный временный каталог. Никакие production-данные не читаются, `docs/` шаблона не создаётся. Проверяются ссылки, совместный канал, статьи, неопределённые даты, истёкший анализ, отключение модулей, сохранение медиа, повторяемость сборки и обновление хеша CSS.

Для ручного просмотра можно создать отдельный учебный проект:

```powershell
python scripts/demo_fixture.py C:/Temp/expo-synthetic-demo
python C:/Temp/expo-synthetic-demo/scripts/build_portal.py
python C:/Temp/expo-synthetic-demo/scripts/check_portal.py C:/Temp/expo-synthetic-demo/docs
```

Каталог назначения должен быть пустым и находиться вне шаблона. Все учебные названия, даты и ссылки маркированы как синтетические; домен `example.example` не является источником фактов. Не публикуйте учебную сборку как реальный портал.
